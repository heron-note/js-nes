# ゲーム1本目: 壁打ちPong

M7（[docs/02_ROADMAP.md](../../docs/02_ROADMAP.md)参照）で用意した、同梱1本目のサンプルゲーム。
DSL v1（シーン/パーツ構成モデル、[docs/03_DSL_SPEC.md](../../docs/03_DSL_SPEC.md)）で書かれている。
ボール(`Ball`)とパドル(`Paddle`)をそれぞれ独立した「パーツ」として定義し、シーン(`Main`)に
インスタンスとして配置している（配列・ループ・複合式を使わない、if/elseの入れ子とヘルパー
フィールドだけで衝突判定を組んでいる点はv0時代と同じ）。

## 遊び方

1. `main.js` 内の `part Ball { ... }` / `part Paddle { ... }` の中身を、それぞれWeb IDE
   （`apps/web`）の「パーツ」タブで作った同名パーツのコードエディタへコピー&ペースト。
   `scene Main { ... }` の中身は「シーン」タブへ同様に貼り付ける。
2. 各パーツの「ドット絵」（パーツ専用のタイルシート）のタイル0番に好きな絵を描く。
3. 「ビルド&実行」を押す。上下キー（またはタッチパッド）でパドルを操作し、跳ね返るボールを打ち返し続ける。

## 実装メモ

- パドルの上下移動は画面外に出ないよう `if (self.y > 2)` / `if (self.y < 224)` でクランプしている
  （`Paddle.move(self)`）。
- 衝突判定（ボールがパドルのY範囲内にいるか）は、DSLが複合式（`self.y + 8`等）を扱えないため、
  毎フレーム `self.bottom = self.y; self.bottom += 8;` を計算してから比較している。
- ボールの壁での跳ね返り（自己完結）と、パドルとの衝突判定（パーツ横断）は別の関心事として分離した:
  - `Ball.checkWalls(self)`: 上下・右の壁での跳ね返り（このパーツだけで完結）。
  - `scene Main`の`update()`内: `ball.x`/`paddle.y`/`paddle.bottom`というパーツをまたいだ状態を
    読むシーンレベルの相互作用ロジック（パドル衝突判定）。
  - `Ball.checkMiss(self)`: 取り逃し（左端到達）時のリセット。パドル衝突判定の**後**に呼ぶことで、
    衝突域と取り逃し域が重なる左端付近でも、リセットが優先されるようにしている。
- 「ANDで複数条件をまとめる」構文がないため、`if`の入れ子で論理ANDを表現している。
- ボールの進行方向は `self.goingRight` / `self.goingDown`（0か1のフラグ）で管理し、
  `if (flag) {...} else {...}` で分岐させている。
- 動作ロジックは `packages/dsl-compiler/src/games.test.ts` でこのファイルをそのままコンパイル・実行して検証している
  （パドルのクランプ、壁での跳ね返り、パドル衝突、ミス時のリセットをフレーム単位でアサート）。
