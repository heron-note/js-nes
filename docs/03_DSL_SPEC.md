# 03. DSL 仕様（v0）

JS 風の書き味を持つ、NES 制約に合わせた専用スクリプト言語。**フル JavaScript 互換ではない**。
「書き慣れた構文で書けるが、吐き出されるのは混じり気なしの 6502 マシン語」というギャップを狙う。

> **実装状況**: v0は `packages/dsl-compiler` として実装済み（M2完了）。`drawSprite`の画面描画もM4（PPUスプライト対応）完了により有効。
> 本ドキュメントは実装済みの仕様を記述する。アセットエディタとのシンボル連携（`SPRITE.xxx`等）はまだ未実装（タイル番号は現状すべて生の数値で指定する）。

## 設計原則

1. **数値はすべて 8bit 符号なし整数（0〜255）** — ファミコンのレジスタ幅に合わせ、演算をすべて1〜数命令に収める。
2. **変数はグローバルのみ・ゼロページ配置** — `let x = 120;` のような宣言を見つけたら、ゼロページ（`$00`〜`$FF`）のアドレスに自動で割り当てる。
3. **関数呼び出しのネストは浅く** — NES のスタック領域は256バイトしかないため、再帰呼び出しは非対応。
4. **ハードウェア専用のビルトイン関数を用意** — PPU/APU のレジスタ操作を直接書かせず、`drawSprite()` 等の定型マシン語に直結した関数を提供する。
5. **エントリポイントは `init()` と `update()`** — NES の NMI（垂直帰線割り込み、毎秒60回）にフックし、`update()` を自動で毎フレーム呼び出す。読者はフレーム同期を意識しなくてよい。

## サンプルコード

```javascript
let x = 120;
let y = 100;

function init() {
  setPalette(0, 1, 33, 0, 0);       // 背景パレット0番に4色設定（背景色 + 3色）
  setSpritePalette(0, 1, 34, 0, 0); // スプライトパレット0番に4色設定
  setSpritePalette(1, 1, 22, 0, 0); // スプライトパレット1番に別の配色を設定
}

function update() {
  if (btn.right) { x += 1; }
  if (btn.left) { x -= 1; }
  if (btn.up) { y -= 1; }
  if (btn.down) { y += 1; }

  drawSprite(0, x, y, 0, 0); // タイル0番をパレット0番の配色で表示
  drawSprite(1, 200, 50, 0, 1); // 同じタイル0番でもパレット1番なら別の配色で表示できる
}
```

## v0 でサポートする構文サブセット（実装済み）

- `let` によるグローバル変数宣言（トップレベルのみ、初期値は数値リテラルのみ。`0x`始まりの16進数リテラルにも対応）
- 代入文: `x = 値;` / `x += 数値;` / `x -= 数値;`（右辺は変数または数値リテラルのみ。`+=1`/`-=1`は`INC`/`DEC`に最適化）
- 比較演算子: `==`, `!=`, `<`, `>`, `<=`, `>=`（`if`の条件式でのみ使用可、`変数 op (変数|数値)`の形のみ）
- 制御構文: `if` / `else`（ブロック`{}`必須。条件式は比較式、または`btn.xxx`/変数の真偽値評価）
- エントリポイントは `init()` と `update()` の2つのみ（両方必須。任意のユーザー定義関数は**v0では未対応**）
- コメント: `//` 行コメント
- ビルトインオブジェクト参照: `btn.right` 等のプロパティアクセス（`btn`のみ対応）
- ビルトイン関数呼び出し文: `setPalette(...)` / `setSpritePalette(...)` / `drawSprite(...)` / `playTone(...)`（引数は変数または数値リテラルのみ）
- `btn.<name>_just_pressed` によるボタン押下のエッジ検出（`btn.<name>`は押しっぱなし判定、`_just_pressed`は押した瞬間のみ）

## v0 でサポートしない構文（意図的に対象外）

- 配列・オブジェクトリテラル、文字列型
- クロージャ、再帰呼び出し、`init`/`update`以外のユーザー定義関数
- `for` / `while` ループ、`for...of` / `for...in`
- テンプレートリテラル、分割代入、スプレッド構文、三項演算子
- `class`、非同期処理（`async`/`await`、Promise）
- 複合式（`x = a + b` のような二項演算の連鎖。`+=`/`-=`による単純な増減のみ）

> 上記は将来的に段階拡張の余地があるが、「ゼロページ256バイト・浅いスタック」というハード制約に見合わない機能（配列的な可変長データ構造、深い再帰、任意個のユーザー関数によるスタック消費等）は方針として恒久的にサポートしない候補が多い。
> ループ非対応は特に大きな制約であり、優先度の高い次期拡張候補。

## ビルトイン API（v0実装済み）

| API | 説明 |
|---|---|
| `setPalette(slot, c0, c1, c2, c3)` | 背景パレットスロット（実機の制約どおり0-3の4枠。範囲外はAND #$03でマスクされる）に4色（NESパレット色番号0-63）を設定。`$3F00 + slot*4`へ書き込む |
| `setSpritePalette(slot, c0, c1, c2, c3)` | スプライトパレットスロット（0-3の4枠）に4色を設定。`$3F10 + slot*4`へ書き込む（`c0`はハード仕様上$3F00に統合され独立した意味を持たない） |
| `drawSprite(id, x, y, tile, palette)` | スプライトID（0-63）を座標(x, y)にタイル番号`tile`・パレット番号`palette`（0-3、`setSpritePalette()`で設定した4枠のどれを使うか）で表示するようOAMシャドウへ書き込み、毎フレームNMI末尾のOAM DMAでPPU側OAMへ反映・画面表示される（8x8固定、1ライン最大8枚。フリップ/優先度は未対応） |
| `btn.up` / `btn.down` / `btn.left` / `btn.right` / `btn.a` / `btn.b` / `btn.start` / `btn.select` | 1コンの現在の押下状態（毎フレームNMI冒頭でキャッシュされた値を参照） |
| `btn.<name>_just_pressed`（例: `btn.a_just_pressed`） | 今フレームで押された瞬間のみ真（エッジ検出。現在の状態と直前フレームの状態から`(現在 XOR 直前) AND 現在`で算出） |
| `playTone(channel, noteIndex, duration)` | チャンネル（0=Pulse1, 1=Pulse2, 2=Triangle, 3=Noise）で音を鳴らす。`noteIndex`はPulse/Triangleなら音階テーブルの番号（0-35、C3〜B5の3オクターブ、等平均律）、Noiseなら実機のノイズ周期インデックス（0-15）を直接指定。`duration`は発音を継続するフレーム数（約1/60秒単位）で、経過後は自動的に無音化する |

未実装（将来拡張候補）: `drawSprite`のフリップ/優先度指定（`palette`以外の属性ビット）、`SPRITE.xxx`/`BGM.xxx`/`SE.xxx`シンボル解決（アセットエディタとのシンボル連携）、BGMシーケンス再生（`playTone`は単発の音のみ）、`btn2.*`（netplay対応時）。

## コンパイルパイプライン

```
ソース文字列
  → トークナイズ（字句解析）
  → AST生成（自作再帰下降パーサ）
  → シンボル解決（変数→ゼロページアドレス割り当て、SPRITE/BGM/SE名→定数値解決）
  → 中間命令列への変換
  → 2パスアセンブル
      1パス目: ラベルのアドレスを記録
      2パス目: 相対ジャンプ・絶対アドレス参照を実アドレスに置換
  → 6502バイト列（PRG-ROM本体）
```

## JS構文 → 6502命令 変換イメージ

| DSL側の記述 | 生成される6502命令列（実装どおり） |
|---|---|
| `let x = 120;` | ゼロページ`$0B`（1つ目のグローバル変数）を`x`に割り当て、resetルーチン内で `LDA #120 / STA $0B` |
| `x += 1;` | `INC $06` |
| `if (btn.right) { ... }` | `LDA $00`（キャッシュ済みボタン状態） `/ AND #$01 / BEQ skip_label` |
| `drawSprite(0, x, y, 1, 0)` | 各引数を`LDA`+`STA`で引数スクラッチ($02-$06)へ積み `JSR draw_sprite` |

ゼロページレイアウト: `$00`=ボタン状態キャッシュ（現在フレーム）、`$01`=ボタン状態キャッシュ（直前フレーム、`_just_pressed`判定用）、
`$02`-`$06`=ビルトイン関数の引数スクラッチ、`$07`-`$0A`=サウンドチャンネルごとの残り発音フレーム数、`$0B`以降=ユーザー宣言のグローバル変数（宣言順）。

## v1: シーン/パーツ構成モデル（M11で追加）

v0の`let`/`function init/update`に加え、`part`/`scene`宣言を追加した（既存のv0構文は無変更・
そのままの意味で使える）。ファミコンのハード制約（ゼロページ256バイト共有・浅いスタック）を踏まえ、
「パーツ種別ごとに1本の再帰なしサブルーチン + インスタンス状態はゼロページではなく通常RAM
（`$0300`-`$07FF`）にSoA配列として確保」という設計で実現している（詳細実装は
`packages/dsl-compiler/src/codegen.ts`のコメント参照）。

```javascript
part Ball {
  field x = 128;       // インスタンスごとのフィールド（初期値は数値リテラルのみ、v0のletと同様）
  field goingRight = 1;

  behavior move(self) {          // このパーツの1インスタンス分の振る舞い。引数は必ず self
    if (self.goingRight) { self.x += 2; } else { self.x -= 2; }
    drawSprite(1, self.x, 120, 0, 0); // tile引数はこのパーツ内でのローカル0起点番号
  }
}

scene Main {
  instance ball: Ball;           // パーツのインスタンスをこのシーンに配置
  instance paddle: Paddle;

  function init() { setPalette(0, 1, 48, 0, 0); }

  function update() {
    Ball.move(ball);             // PartType.behaviorName(instanceName); で振る舞いを実行
    // instanceName.field でパーツをまたいだ状態の読み書き（当たり判定等はここに書く）
    if (ball.x < 28) {
      if (ball.y > paddle.y) { ball.goingRight = 1; }
    }
  }
}
```

- `part`/`scene`を1つでも使う場合、トップレベルの`function init/update`は使用できない
  （sceneの`init`/`update`を使う）。`scene`は現状ちょうど1つのみ（複数シーンの切り替えは未対応）。
- `self.field`はbehavior内でのみ、`instanceName.field`はscene内でのみ使用できる。
- `drawSprite(...)`のtile引数（数値リテラルの場合のみ）は、そのパーツ専用のタイルシート内での
  ローカル0起点番号として扱われ、ビルド時（`apps/web/src/projectBuild.ts`のアセットリンク）に
  他パーツと重複しないグローバルなCHR-ROM番号へ自動変換される。
- 音も名前付きアセットとして扱い、コード中の`playSound(名前)`（DSL自体の構文ではなく、
  Web IDEのプロジェクトビルド時に`playTone(channel, noteIndex, duration)`へ機械的に置き換えられる
  糖衣構文）として呼び出せる。`compile()`自体は`playSound`を認識しない点に注意
  （`games/game-01-pong/main.js`のような生の`.js`ソースを直接`compile()`に渡す場合は
  `playTone(...)`を直接書く）。

## エラー・制約の扱い方針

現状（v0実装）では、ゼロページの枯渇（256バイト超過）・未宣言変数の参照・`init`/`update`の欠落などは
コンパイル時に例外（`ParseError` / `CodegenError`）として投げられ、Web IDEの「ビルド&実行」タブ上にエラーメッセージとして表示される。
ゼロページ枯渇時のメッセージは「ゼロページ（256バイト）がパンクしました！」のように、当初構想の「実機の制約を楽しむ」トーンを踏襲している。
スプライト同一ライン9個超過などPPU側の制約可視化は、PPUのスプライト対応（M4）実装後に追加する。

## 未決事項（要検討）

- `while` / `for` ループの対応可否と、対応する場合の安全策（無限ループ防止のための静的チェック等）— 優先度高
- 複合式（`x = a + b` 等）や配列的なデータ（タイルマップ等）を扱いたい場合の構文拡張
- `init`/`update`以外のユーザー定義関数（浅いネストのみ許可する案）のサポート要否
- エラー表示をUI上の「警告バッジ」的な演出に昇華するか（現状は素朴なエラーメッセージ表示のみ）
