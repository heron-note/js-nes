# 06. オンライン対戦仕様（ストレッチゴール）

> 本機能は [02_ROADMAP.md](02_ROADMAP.md) の M8/M9（ストレッチゴール）に位置づけられる。
> コアの「DSLコンパイラ + アセットエディタ + エミュレータ本体」（M1〜M6）が完成した後に着手する。
>
> **実装状況（UI）**: Play メインからは外し、カセット操作横の「対戦」→モーダル。役割は「部屋を作る／入る」のウィザード。同期方式は折りたたみ。接続状態は細いバッジのみ。シグナリングの手動往復はモーダル内に残置（簡易化は後続）。
>
> **実装状況（M8 Phase1）**: `apps/web/src/netplay.ts` の `NetplayHost` / `NetplayGuest`。
> signalingサーバーを持たないため、オファー/アンサーをBase64文字列にエンコードし、招待コードとして手動コピペでやり取りする方式を採用
> （ICE Trickleは使わず、ICE収集完了を待ってから1本のコードにまとめるため往復は1回で済む）。
> ブラウザで実際に2タブ間の接続を検証し、シグナリング（オファー/アンサー交換）・ICE・
> RTCPeerConnectionが両者とも `connected` 状態に到達することを確認済み。
>
> **実装状況（M9 骨格）**: 同ファイルの `LockstepHost` / `LockstepGuest` と `netplayLockstep.ts`。
> 接続後に DataChannel で ROM をチャンク転送し、双方の Worker を `lockstepEnable`＋`stepFrame` で
> フレーム駆動する。入力は数バイト/フレーム＋入力遅延バッファ（既定2フレーム）。
> 60フレームごとに framebuffer ハッシュを交換してデシンク検出する。
> UI の「同期方式」で Phase1 と切替可能。実地の対戦検証は未完了（骨格として先行実装）。
>
> 一方、映像（`captureStream()`）がゲスト側に届く様子は、この開発で使った自動化ツールが
> ホスト側タブを非表示扱いしrAFの描画ループが進まない（詳細は[02_ROADMAP.md](02_ROADMAP.md)のM5/M6注記）ため、
> `captureStream()`が新しいフレームを生成できず未確認（実際のユーザーのフォアグラウンドタブでは問題ない見込み）。
> DataChannel経由のゲスト→ホスト入力反映（`applyGuestButtons`）はコードレビューでの確認に留まり、実接続での
> エンドツーエンド検証はできていない。

## 狙い

ファミコンの1コン/2コンを、専用サーバーなしでブラウザ同士を直接つなぎ、NATを越えてオンライン対戦できるようにする。

## 通信方式

- **WebRTC DataChannel** によるブラウザ間 P2P 直接通信。サーバーを介した中継が不要なため通信遅延が極小（数ミリ秒〜数十ミリ秒）で、サーバーコストもほぼゼロ。
- **NAT越え**: ルーターやファイアウォールを越えるため、Google等の公開無料STUNサーバーを利用。
- **シグナリング**: 接続開始時にお互いを認識するための情報交換が必要。初期実装は「招待URL（接続情報をハッシュに載せる）」による手動交換、または軽量な既存ライブラリ（PeerJS等）の利用を検討する（未確定）。

## 同期方式

ファミコンのマルチプレイ同期で送るべきは「ゲームの巨大な状態（座標・体力等）」ではなく、
**「コントローラのボタン状態（わずか1バイト）」だけ**でよいという点がシンプルさの鍵。

| 方式 | 仕組み | メリット | デメリット | 採用フェーズ |
|---|---|---|---|---|
| ① 画面ストリーミング型 | ホストのエミュレータ画面（`<canvas>`）を `captureStream()` でWebRTC映像として配信 | 状態のズレ（デシンク）が原理上100%発生しない。ゲスト側はROMすら不要 | 映像遅延・帯域消費がわずかに発生 | **M8（先行実装）** |
| ② 入力ロックステップ型 | 接続時にROMを渡し、両者が同じROMを実行。毎フレーム1P/2Pのキー入力（各1バイト）だけを送り合う | 映像遅延なし、両者とも最高画質・フレームレートで滑らか。乱数は送らず決定性で一致 | パケットロス等で一度ズレると世界が分岐（デシンク）する。対策実装が必要 | **M9（骨格実装済み・検証途上）** |

対戦アクション/格闘のようなジャンルでも、まずはズレる心配が一切ない **①画面ストリーミング型** から着手する。

## ロール分担（入力ロックステップ型の場合）

- **ホスト（1P）**: 手元の ROM（ビルド成果 or カセット）を DataChannel でゲストへ送る。双方が同じバイト列を `loadRom` する。
- **両者**: Worker をロックステップモードにし、揃った `(p1, p2)` 入力でだけ `stepFrame` する。
- **入力遅延**: 既定2フレーム。自分の入力もバッファ経由で遅らせ、相手待ちの体感差を平準化する。
- **デシンク検出**: 60フレームごとに framebuffer の簡易ハッシュを交換。不一致なら停止して通知（再同期は未実装）。
- **乱数**: 送信しない。同じ初期状態＋同じ入力なら疑似乱数も一致する前提（非決定要因の排除が今後の課題）。

## ロール分担（画面ストリーミング型の場合）

- **ホスト（部屋を作った人 / 1P）**: エミュレータ本体を実行。自分のキーボード入力を1コン（`$4016`）へ、
  リモートから届いたボタン入力を2コン（`$4017`）へ渡す。
- **ゲスト（部屋に入った人 / 2P）**: 自分のコントローラ入力（1バイト）を毎フレームホストへ送信するのみ。
  画面はホストからのWebRTC映像ストリームを受信して表示する（ROM実行不要）。

## UI/UXフロー（方針）

**メインの Play 画面をオンライン対戦 UI で占有しない。** 常時表示のホスト／ゲスト二列・巨大テキストエリアは廃止対象。

### 配置

- Play 本体はカセット・画面・パッドが主役
- 対戦は **小さな導線だけ**（例: メニュー／「…」／ツールバーの「対戦」）。押すと **ポップアップ（モーダル）** が開く
- 接続中もメインを食わない。状態は細いバッジ（「対戦中・切断」）程度。詳細はまたポップアップ
- Play 先行公開時は対戦を推さない（導線は残してもよいがデフォルト閉じ・β 扱い可）

### モーダル内の流れ（目標 UX）

役割を最初から両方出さない。ウィザードにする。

1. **部屋を作る** or **部屋に入る** を選ぶ
2. ホスト: 招待を **1つ** 出す（短いコード／QR／共有リンク）。ゲストに渡す
3. ゲスト: それを貼る／リンクを開く → 参加
4. 可能ならホスト側の「応答コードを貼る」往復を消す（下記シグナリング）

現状実装の「招待コード ↔ 応答コードの手動往復」は開発用フォールバックとし、公開 UX の本線にしない。

### やり取りの簡易化（検討順）

| 案 | ゲストの操作 | サーバー | 備考 |
|---|---|---|---|
| A. 共有リンク（offer を URL ハッシュ／短縮） | ゲストはリンクを開くだけ | 短縮時のみ軽い intermediary | 仕様書当初案に近い。応答の返し方を別途要設計 |
| B. 短い部屋コード + 既存 Workers でシグナリング | コード 6 文字程度を口頭／チャットで伝える | あり（短命・容量小） | GitHub 認証用 Workers と同居しうる。UX 最良候補 |
| C. 手動コピペ往復（現状） | 双方テキストエリア | なし | デバッグ／オフライン用にモーダルの「詳細」へ隠す |

公開向けは **B（または A+短い応答）** を本線にし、メイン画面には出さない。同期方式（stream / lockstep）の切替もモーダル内の折りたたみか上級者向け。

### 接続後

- ゲスト映像用 `<video>` もモーダル内か、メイン canvas と切り替え（常時並置しない）
- 切断はパッド付近の小さな「切断」か、同じポップアップから

## DSL側の扱い

コードを書く側（読者）はNATやWebRTCの存在を意識しなくてよい設計とする。

```javascript
function update() {
  // 1コン（ホスト）
  if (btn1.right) p1_x += 1;
  if (btn1.left) p1_x -= 1;

  // 2コン（リモート参加者）
  if (btn2.right) p2_x += 1;
  if (btn2.left) p2_x -= 1;

  drawSprite(0, p1_x, p1_y, SPRITE.PLAYER1, 0);
  drawSprite(1, p2_x, p2_y, SPRITE.PLAYER2, 1);
}
```

`btn2.*` は現状の [03_DSL_SPEC.md](03_DSL_SPEC.md) のビルトインAPIには未定義であり、netplay着手時に追加する（M8での拡張項目）。
