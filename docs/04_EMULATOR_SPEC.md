# 04. エミュレータ本体仕様

> 本ドキュメントは開発チーム向けの内部実装方針である。[00_CONCEPT.md](00_CONCEPT.md) の方針どおり、
> **エミュレータ内部の解説は note 連載の主役にはしない**（連載では「動いて当然の舞台装置」として提示する）。

## スコープ（更新: フル機能化後）

当初スコープは「Mapper 0（NROM）で動くゲームが正しく実行できること」だった。その後、
「拡張マッパーも動くのか」という指摘を受けて実施したフル機能化（[02_ROADMAP.md](02_ROADMAP.md) M9参照）により、
**PPUスクロール・6種のマッパー・実機同等のサイクル駆動APU**まで対応範囲を広げた。

ただし「あらゆる市販ROMが完璧に動くフル互換機」ではない。本ドキュメントは実装済みの範囲と、
まだ対応していない項目（未実装項目）の両方を正直に列挙することを目的とする。

## CPU（MOS 6502 互換 / Ricoh 2A03）

### 実装済み

- クロック: 約1.79MHz相当（実クロック同期ではなく、フレーム単位でCPU/PPU/APUのステップ数を管理）。
- ディスパッチ方式: オペコードテーブル（256要素の関数配列）による分岐。
- **公式命令56種・151オペコードすべて実装済み**（`packages/emulator-core/src/cpu.ts`）。
- `irq()`/`nmi()`ともに実装済みで、マッパー（MMC3のスキャンラインIRQ等）・APU（フレームIRQ・DMC IRQ）の
  両方からNes.runFrame()経由で実際に発火する（[06_NETPLAY_SPEC.md](06_NETPLAY_SPEC.md)は無関係）。

### 未実装・既知の制約

- **未定義命令（裏命令、いわゆるillegal opcode）は非対応**。105個ある未定義オペコードのうち実装されているものはない。
  一部の市販ソフト・テストROMはこれに依存しており、そうしたROMは正しく動かない。
- **`nestest.nes`による実機ログとの厳密な照合は未実施**。本ドキュメントには当初から「検証方法」として
  記載されていたが、`tools/nestest-diff/` 自体が一度も作られておらず、CPU実装の正しさは
  `cpu.test.ts`（オペコード単位のユニットテスト）とDSLコンパイラが生成したROM群の統合テストでのみ
  検証されている（意味的な実装レベルの検証であり、サイクル精度・フラグ挙動の1bit単位の証明ではない）。
- サイクル数は「基本サイクル + ページ跨ぎ加算 + 分岐成立加算」で近似しており、一部のRMW命令のアドレッシング
  モード等、実機で常に最大値を取るケースは基本サイクル自体に織り込む形で近似している（詳細は`cpu.ts`冒頭コメント参照）。

## PPU（Picture Processing Unit / Ricoh 2C02）

### 実装済み

- **ドット/サイクル精度のレンダリングパイプライン**（`ppu.ts`、PPUのドット精度化プロジェクトで刷新）:
  実機同様のloopy v/t/x/wスクロールレジスタと、背景の8bitラッチ+16bitシフトレジスタによる
  1dot=1ピクセルのフェッチ/シフト/サンプリングパイプラインで描画する。フレーム内で`$2005`/`$2006`/
  `$2000`をミッドスキャンラインで書き換えれば、以降のdotへ即座に反映される（ステータスバー分割等の
  ラスタートリックに対応）。スプライトもdot 65での二次OAM評価・dot 257-320でのパターンフェッチ・
  dot 1-256での背景との合成という、実機と同じタイミングのドット単位パイプラインで動作する。
- **スプライト**: OAM・8x8/8x16（`$2000`bit5で切替。8x16はタイル番号bit0でパターンテーブルを
  選択し、垂直反転時は上下のタイル自体も入れ替わる実機どおりの挙動）・属性バイトのフリップ(H/V)・
  背景優先ビット・8スプライト/ライン制限（9枚目以降で`$2002` bit5のオーバーフローフラグを立てる、
  評価件数ベースの簡略実装。実機の「対角読み出しバグ」までは再現しない）・スプライト0衝突フラグに対応。
- **PPU A12エッジ通知**（`PpuBus.ppuA12`）: 背景・スプライトのパターンテーブルフェッチのたびに、
  そのアドレスのbit12を実際に通知する。MMC3のスキャンラインIRQ（後述）はこれで駆動する。
- **ミラーリング**: horizontal/vertical/single-screen-a/single-screen-b（AxROM・MMC1が動的に切り替え可能）。
- 出力: 256×240の`ImageData`（RGBA配列）へ直接ピクセルを書き込み、`putImageData`で`<canvas>`に転送。

### 未実装・既知の制約

- **スプライトオーバーフローフラグの判定は実機の「対角読み出しバグ」を再現しない**
  （評価件数が8件を超えた時点でフラグを立てるだけの簡略実装。バグに依存するROMは対象外）。
- **four-screenミラーリングは実質未対応**（型としては受け付けるが、内部ではverticalへフォールバックする
  だけの暫定実装。4枚分の独立ネームテーブルRAMが必要だが、対応中のマッパーでは実質使われないため後回しにした）。

## APU（Audio Processing Unit）

### 実装済み（フル機能化のPhase 5a/5bで刷新）

当初（M5時点）は「レジスタ生値を保持し、そこから毎フレーム導出したスナップショットを返すだけ」の
簡易実装だったが、実機同様にCPUサイクル駆動でクロックする実装に全面刷新した。

- **フレームシーケンサ**（4-step/5-step、`$4017`で切替）: quarter-frame/half-frameクロックで
  エンベロープ・三角波リニアカウンタ・レングスカウンタ・スイープを実機と同じタイミングで駆動。
- **エンベロープ減衰**: constant-volume=0時に実際に時間経過で音量が減衰する。
- **スイープ**: 矩形波の周期を実機同様に自動変化させる（ミュート条件も再現）。
- **レングスカウンタ**: haltビットが立っていない限り時間経過で0になりチャンネルが無効化される
  （実機同様、`$4003`/`$4007`/`$400B`/`$400F`への書き込みで初めてロードされる。書かないと音量に関わらず
  無音のままになる点に注意——本フル機能化の過程で、DSLコンパイラのノイズSEがこの書き込みを欠いており
  実機上は常に無音になるはずだった潜在バグが見つかり、あわせて修正した）。
- **三角波のリニアカウンタ**: reloadフラグ方式で実機同様に遅延ロードされる。
- **ノイズ**: 実機の15bit LFSR疑似乱数（short/longモードのタップ切り替え）で実際にビット列を生成する。
- **DMCチャンネル**: レート/サンプルアドレス/長さレジスタ、8bitシフトレジスタによるデルタ出力、
  メモリ読み出し（Nes側からのコールバック注入）、IRQに対応。
- **出力パイプライン**: `Apu.getMixedSample()`（実機のミキサー式による非線形合成）→
  `Apu.drainSamples()`でPCMサンプル列を取り出し、`AudioWorkletProcessor`
  （`apps/web/src/audio-worklet-processor.js`）で再生。従来の`OscillatorNode`近似実装は廃止した。

### 未実装・既知の制約

- **DMCのメモリ読み出しによるCPUサイクルの盗み（stall）は再現しない**。実機はDMCがサンプルを
  読み出すたびにCPUを最大4サイクル停止させるが、本実装ではこれをモデル化していないため、DMCを
  多用するROMではCPUタイミングにわずかな誤差が生じる可能性がある。
- **フレームシーケンサの書き込み後ディレイ**（実機は`$4017`書き込みから3-4サイクル後に反映）は
  即座反映として近似している。
- **PAL/Dendyタイミングは非対応**（NTSC固定。CPU/PPUのクロック比・フレームタイミング定数がハードコード）。

## マッパー（Cartridge / Mapper）

### 実装済み

`packages/emulator-core/src/mapper.ts`の`createMapper()`が対応マッパーIDに応じてインスタンスを生成する。

| Mapper ID | 名称 | 対応内容 |
|---|---|---|
| 0 | NROM | PRG16/32KB固定、CHR-ROM/RAM |
| 1 | MMC1 | シリアルシフトレジスタ、PRG/CHR各種バンクモード、動的ミラーリング、PRG-RAM |
| 2 | UxROM | PRG16KB可変+最終バンク固定、CHR常にRAM |
| 3 | CNROM | PRG固定、CHR8KB可変 |
| 4 | MMC3 | bank-select/data間接方式、PPU A12エッジ駆動のスキャンラインIRQ（フィルタ付き）、PRG-RAM protect |
| 7 | AxROM | PRG32KB丸ごと可変、動的シングルスクリーンミラーリング |

この6マッパーは、拡張マッパー非対応のホームブリュー作品の大半（NROM/UxROM/MMC1が中心）と、
MMC3を使う本格的な作品の一部をカバーする。実際にCC0/パブリックドメインのホームブリューROM
「Lawn Mower」（Shiru氏, Mapper 0）を読み込ませ、タイトル画面の描画とBGM再生を確認済み。

### 未実装・既知の制約

- **上記6種以外のマッパーは非対応**（未対応IDのROMを読み込むと`createMapper()`が
  例外を投げ、明示的にエラー表示される）。特に以下は未対応:
  - VRC1/VRC2/VRC3/VRC4/VRC6/VRC7（コナミ）
  - MMC5（拡張音源・大容量バンク切り替え）
  - Namco 108/163
  - Sunsoft FME-7
  - その他iNESフォーマットに存在する多数のマイナーマッパー
- **バッテリーバックアップされたPRG-RAM（MMC1/MMC3のセーブデータ）は永続化されない**。
  ブラウザのメモリ上に保持されるだけで、リロード・タブを閉じると消える
  （localStorage等への保存は未実装）。

## 外部.nesファイルの読み込み

Web IDEの「ビルド&実行」タブから、DSLコンパイルを経由せず任意の`.nes`ファイルを直接読み込んで
実行できる（`apps/web/src/main.ts`のROMアップロード機能）。対応マッパー（上表の6種）の範囲であれば、
ホームブリュー等の第三者制作ROMの動作確認に使える。著作権上、市販ROMの吸い出しデータを読み込ませる
用途は想定していない（[00_CONCEPT.md](00_CONCEPT.md)の非ゴール参照）。

## メモリマップ（概要）

| アドレス範囲 | 用途 |
|---|---|
| `$0000`–`$07FF` | 内部RAM（うち `$0000`–`$00FF` がゼロページ、DSLのグローバル変数割り当て先） |
| `$0800`–`$1FFF` | 内部RAMのミラー |
| `$2000`–`$2007` | PPUレジスタ |
| `$2008`–`$3FFF` | PPUレジスタのミラー |
| `$4000`–`$4013` | APUレジスタ |
| `$4014` | OAM DMA |
| `$4016`–`$4017` | コントローラ入力レジスタ / APUフレームカウンタ（`$4017`書き込み） |
| `$6000`–`$7FFF` | マッパーのPRG-RAM（MMC1/MMC3等が使用。NROM/UxROM/CNROM/AxROMでは未使用） |
| `$8000`–`$FFFF` | PRG-ROM（マッパーごとのバンク切り替えルールに従う） |

## 入力

- 標準コントローラの `$4016`（1コン）/ `$4017`（2コン）のシリアル読み出しに `keydown` / `keyup` イベントをマッピング。
- 将来のオンライン対戦（[06_NETPLAY_SPEC.md](06_NETPLAY_SPEC.md)）では、リモートから届いた入力バイトをこの層に合流させる。

## 描画同期

- `requestAnimationFrame` に合わせ、1フレーム（約16.6ms）分のCPU/PPU/APUクロックをまとめて進める。
- フレームスキップ・可変フレームレート環境への対応は将来課題（初期は固定60fps前提）。

## ROM 読み込み

- `.nes` 形式（iNESヘッダー付き）のバイナリを `Uint8Array` として読み込み、先頭16バイトをパースして
  PRG-ROM / CHR-ROM のサイズ・配置・Mapper番号・ミラーリング設定を切り分ける。
- 自作ツールで生成したROM、および対応マッパー範囲の外部`.nes`ファイル（上記「外部.nesファイルの読み込み」参照）
  の両方をロード可能。
