# 05. アセットエディタ仕様（ドット絵 / 音源）

コード・ドット絵・チップチューンをタブ1つでシームレスに繋ぎ、JS風DSLからアセット名で直接呼び出せ、
ビルド時にハードウェア準拠のバイナリへ自動変換される「ブラウザ完結のファミコン統合IDE」の中核機能。

## 1. キャラクター/タイルエディタ（CHR-ROMビルダー）

ファミコンのグラフィックは「2bpp（1ピクセル2ビット＝4色: 透明+3色）」という独特のプレーン構造を持つ。これを直感的なグリッドUIで編集させる。

### UI仕様

- **キャンバス**: 8×8ピクセル（1タイル単位）を基本とし、16×16（2×2タイルのキャラクター単位）の複合編集にも対応。
- **パレット選択**: NES標準の全64色パレットから「透明 + 任意3色」を選ぶセレクターを併設。
- **タイル一覧（シート）**: 最大256タイルが並ぶスプライトシートビュー。各タイルに `PLAYER_STAND`, `ENEMY_SLIME` のような**シンボル名**を付けられる。

### DSLコードからの呼び出し

```javascript
drawSprite(0, x, y, SPRITE.PLAYER_STAND, 0);
```

### ビルド時のバイナリ変換

- 編集中のドット絵（各ピクセルが0〜3の値を持つ配列）を、ビルド時に「Plane 0（下位ビット、8バイト）＋ Plane 1（上位ビット、8バイト）」のファミコンCHR-ROM形式（1タイル=16バイト）にビット演算でパッキングする。
- 全タイルを連結した CHR-ROM（NROM構成では通常8KB）として `rom-builder`（[01_ARCHITECTURE.md](01_ARCHITECTURE.md)）に渡す。
- エディタで付けたシンボル名（`SPRITE.PLAYER_STAND` 等）は、ビルド時にタイルIDの定数値へ解決される（[03_DSL_SPEC.md](03_DSL_SPEC.md) のシンボル解決フェーズ）。

## 2. チップチューン音源エディタ（APUトラッカー）

> **実装状況（M5時点）**: ファミコン準拠4チャンネルのAPU実装とDSLの `playTone(channel, noteIndex, duration)` ビルトインは
> 実装済み（[03_DSL_SPEC.md](03_DSL_SPEC.md)、[04_EMULATOR_SPEC.md](04_EMULATOR_SPEC.md)）。Web IDEの「音源」タブは
> 現状、チャンネル状態のリアルタイムモニタ（音量・周波数の可視化）のみで、以下で説明するマウスでの打ち込み編集UI
> （ステップシーケンサー）自体はまだ未実装。BGMのような複数音符のシーケンス再生も未対応（現状は単発の音のみ）。

ファミコン準拠の4チャンネル（矩形波×2、三角波、ノイズ）をマウス入力で打ち込める、ミニマルなステップシーケンサー（将来実装）。

### チャンネル構成（NES APU仕様準拠）

| チャンネル | 設定可能項目 | 主な用途 |
|---|---|---|
| SQ1 / SQ2（矩形波） | デューティ比（12.5% / 25% / 50% / 75%）、音量 | メロディ・ハーモニー |
| TRI（三角波） | 音量調整不可（鳴るか止まるかのみ） | ベースライン・バスドラム |
| NOISE（ノイズ） | 周期（音程）、短周期モード（金属音） | スネア・爆発音 |

### エディタの機能

- **BGM用**: 16〜32ステップのループパターン作成（ピアノロール or ステップシーケンサーUI）。
- **SE（効果音）用**: 数フレームで周波数が急激に変化するプリセット（ジャンプ音、コイン取得音など）をスライダーで作成。

### DSLコードからの呼び出し

```javascript
function init() {
  playMusic(BGM.OVERWORLD);
}

function update() {
  if (btn.a_just_pressed) {
    playSound(SE.JUMP);
  }
}
```

### ビルド時のバイナリ変換

- 打ち込んだ音符データ（ノート番号・音長・音量）を、軽量な中間バイト列（MMLやFamiTrackerの極小サブセットに相当）にコンパイルする。
- PRG-ROM側に組み込まれた「超軽量サウンドドライバー」（[04_EMULATOR_SPEC.md](04_EMULATOR_SPEC.md) 参照、数十行の6502アセンブラルーチン）にこのデータを渡し、NMI割り込みのたびにAPUレジスタ（`$4000`〜`$400F`）を更新させる。
- シンボル名（`BGM.OVERWORLD`, `SE.JUMP` 等）はDSLコンパイル時に定数値へ解決される。

## 3. パレットピッカー

- NES固定の64色パレットテーブルを提示し、スプライト/背景それぞれに4色（うち1色は透明）のパレットスロットを設定する。
- `setPalette(slot, [色1, 色2, 色3, 色4])` としてDSLコードからも操作可能（[03_DSL_SPEC.md](03_DSL_SPEC.md)）。

## 4. ビルドパイプラインにおける位置づけ

| 構成要素 | エディタ上のデータ | 変換先（ファミコンバイナリ） |
|---|---|---|
| ヘッダー | 設定画面（タイトル、ミラーリング設定） | iNESヘッダー（16バイト） |
| プログラム | JS風DSLコード（AST解析後） | PRG-ROM（6502マシン語コード） |
| サウンド | APUトラッカーのシーケンスデータ | サウンドドライバ用データテーブル（PRG-ROM末尾） |
| グラフィック | ドット絵キャンバスのピクセルデータ | CHR-ROM（2bppビットプレーン配列） |

これらすべてを `Uint8Array` として結合し、ひとつの完全な `.nes` ファイル（Mapper0構成なら概ね24KB前後）にパッキングする（`rom-builder`）。

## タッチデバイス対応

本プロジェクトはレスポンシブUIを方針とする（[01_ARCHITECTURE.md](01_ARCHITECTURE.md) の「UI/UX方針」参照）。ドット絵エディタ・APUトラッカーは以下に留意する。

- ドット絵エディタのグリッドセル、パレットスワッチ、APUトラッカーのステップセルは、タップ操作を前提とした最小タップターゲットサイズを確保する。
- ピンチズームでのタイル拡大縮小など、狭い画面でも精密な編集ができる操作手段を検討する。
- スマホ幅では、タイルシート一覧とキャンバス編集領域を1画面に収めず、タブ/アコーディオンで切り替える構成を基本とする。

## 既知の制約（M4実装時点）

- DSL v0（[03_DSL_SPEC.md](03_DSL_SPEC.md)）にはネームテーブル（背景タイル配置）を操作するAPIがない。
  ネームテーブルは常に全ゼロ（＝タイル番号0）のままになるため、背景描画自体をコンパイル後のROMで
  無効化している（PPUMASKで背景を常時オフ、スプライトのみ描画）。これにより、タイルシートのどの
  番号を編集しても意図せず画面全体に敷き詰められることはない。ネームテーブル操作APIを追加する際に、
  背景描画の有効化とあわせて対応する想定（未決事項参照）。
- スプライトの画面表示はM4で対応済み（`drawSprite`が実際に画面に出る）。ただしパレットは背景用
  （`setPalette`）とスプライト用（`setSpritePalette`）が別系統なので、エディタのプレビューパレットと
  実行時に見える色が一致するとは限らない。

## 未決事項

- タイルマップ（背景の配置情報）をエディタでどう編集させるか、またはDSLにネームテーブル操作APIを追加するか（上記の既知の制約の根本解決）。
- スマホ幅でのドット絵編集・音源打ち込みの操作性は実装後の実機検証で調整する。
