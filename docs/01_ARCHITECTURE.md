## コンポーネント一覧

### 1. emulator-core（NES エミュレータ本体）

- **CPU**: MOS 6502 互換（Ricoh 2A03）。命令ディスパッチはオペコードテーブル（関数配列）方式。
  初期は必要命令のサブセットから実装し、`nestest.nes` のログ突合で正しさを検証しながら拡張する。
- **PPU**: Ricoh 2C02。スキャンライン単位の実装を優先し、サイクル単位の精度は後回し。
  背景（ネームテーブル/パターンテーブル）描画を先に作り、スプライト（OAM・8スプライト制限・スプライト0衝突）を後続で追加。
  出力は `ImageData`（256×240 RGBA）に直接書き込み、`putImageData` で `<canvas>` に転送。
- **APU**: 矩形波×2・三角波×1・ノイズ×1・DMC×1。M10でCPUサイクル駆動のフル実装（エンベロープ・スイープ・
  レングスカウンタ・実機ノイズLFSR）に刷新し、`AudioWorklet`で実PCM再生する方式に変更した
  （M5時点は簡易スナップショット+`OscillatorNode`近似だった。詳細は[04_EMULATOR_SPEC.md](04_EMULATOR_SPEC.md)）。
- **Mapper**: 初期は **Mapper 0（NROM）のみ**だったが、M10でMMC1/UxROM/CNROM/MMC3/AxROMを追加（計6種）。
  VRC系・MMC5等、まだ対応していないマッパーも多い（詳細は[04_EMULATOR_SPEC.md](04_EMULATOR_SPEC.md)）。
- **入力**: 標準コントローラレジスタ（`$4016`/`$4017`）のシリアル読み出しに `keydown`/`keyup` をマッピング。将来的にリモート入力（netplay）もここに合流させる。
- 詳細仕様は [04_EMULATOR_SPEC.md](04_EMULATOR_SPEC.md)。

### 2. dsl-compiler（JS風 DSL コンパイラ）

- ブラウザ上で完結する自作コンパイラ。フル ES 文法は扱わず、ゲーム制作に必要な範囲のサブセットのみサポート。
- パイプライン: ソース文字列 → トークナイズ → AST（自作再帰下降パーサ） → シンボル解決（変数のゼロページ割り当て） → 中間命令列 → 2パスアセンブル（ラベル解決） → 6502 バイト列。
- ビルトイン関数（`drawSprite`, `btn.*`, `playMusic`, `playSound`, `setPalette` 等）は、あらかじめ PRG-ROM に組み込まれた固定ランタイムルーチンの呼び出し（`JSR`）に変換される。
- NMI（垂直帰線割り込み）ハンドラの中から `update()` を自動で呼び出すジャンプを埋め込み、読者はフレーム同期を意識せずに書ける。
- 詳細仕様は [03_DSL_SPEC.md](03_DSL_SPEC.md)。

### 3. rom-builder（ROM パッキング）

- iNES ヘッダー（16バイト）+ PRG-ROM（コンパイル済みコード＋サウンドドライバ＋音楽/SEデータテーブル）+ CHR-ROM（2bppタイルデータ）を `Uint8Array` として連結し、`.nes` ファイルを生成する。
- ドット絵エディタのピクセルデータ（0〜3の値の配列）を、ファミコン特有の「Plane 0（下位ビット）+ Plane 1（上位ビット）」形式にビット演算でパッキングする。
- カートリッジラベル風画像（タイトル・作者名・ドット絵入り）の自動生成もここで担う。
- スタンドアロン配布用 HTML（自作エミュレータ＋ROMを1ファイルに同梱）の書き出し機能もここに含める。

### 4. sound-driver（サウンドドライバ）

- 軽量な 6502 アセンブラ製サウンドドライバ（数十行程度）。NMI 毎に APU レジスタ（`$4000`〜`$400F`）を、
  APUトラッカーで作成した中間バイト列（音符番号・音長・音量のシーケンス）に従って更新する。
- PRG-ROM の固定領域として同梱される「変更しない共通コード」。

### 5. apps/web（Web IDE 本体）

- M11より、プロジェクトは「パーツ（ドット絵+振る舞い）」「シーン（パーツの配置+進行ロジック）」
  「サウンド（名前付きアセット）」の集まりとして保存・編集する（`apps/web/src/project.ts`）。
  タブ切り替え式のダッシュボードUI: `パーツ` / `シーン` / `音源` / `ビルド&実行` / `オンライン対戦`。
  パーツ/シーンはそれぞれ専用のコード/ブロックエディタを持ち（`コード`⇔`ブロック`のサブタブ）、
  パーツは専用のドット絵タイルシートも持つ。ビルド時に全パーツ+シーンを1本のDSLソースへ結合し
  （`apps/web/src/projectBuild.ts`）、パーツごとのタイルを1本のCHR-ROMへ連結する
  （dsl-compilerの資産リンク機能、[03_DSL_SPEC.md](03_DSL_SPEC.md)参照）。
- **M12（進行中）**: 上記は公開前の中間形。正本はマッパーを根にしたツリー型 v3
  （[09_CREATE_PROJECT_MODEL.md](09_CREATE_PROJECT_MODEL.md)、`apps/web/src/projectV3.ts`）。
  エクスプローラで資産を辿り、ID 参照で紐づけ、編集はブロック主・コード従とする。
- エミュレーション本体（`Nes.runFrame()`のステップ実行）は専用Web Worker（`apps/web/src/nesWorker.ts`）
  で自走させ、メインスレッドの`requestAnimationFrame`ループ（描画・DOM操作等で詰まりうる）から
  音声生成・配信を切り離している。メインスレッドはWorkerから届いた最新のフレームバッファを
  ベストエフォートで`<canvas>`へ描画するだけで、音声はAudioWorkletNodeの`.port`をWorkerへ
  直接譲渡してメインスレッドを一切経由せずに配信する（詳細は[04_EMULATOR_SPEC.md](04_EMULATOR_SPEC.md)参照）。
- 任意で CRT 風シェーダー（走査線・にじみ）をトグル表示できるようにする（本物らしさの演出、優先度低）。
- ソースコードを圧縮して URL ハッシュに埋め込み、ワンクリックで再生・編集できるシェアリンク機能。

### 6. netplay（オンライン対戦、ストレッチゴール）

- WebRTC DataChannel + 無料 STUN サーバーによる P2P 直接通信（NAT 超え、専用中継サーバー不要）。
- Phase 1: ホストの `<canvas>` を `captureStream()` で映像配信する「画面ストリーミング型」（デシンクが原理上発生しない）。
- Phase 2（将来）: 両者が同じ ROM を実行し、コントローラ入力バイトのみを毎フレーム交換する「入力ロックステップ型」（低遅延だがデシンク対策が必要）。
- 詳細仕様は [06_NETPLAY_SPEC.md](06_NETPLAY_SPEC.md)。

## 技術スタック

| 役割 | 採用技術 | 備考 |
|---|---|---|
| 言語 | TypeScript | エミュレータ・コンパイラ・UI すべて共通言語で統一 |
| ビルドツール | Vite | 高速な開発サーバーとバンドル |
| パッケージ管理 | npm workspaces | モノレポ構成。追加ツール導入なしで完結 |
| 画面描画 | Canvas 2D API (`putImageData`) | 256×240 のピクセル配列を直接転送。CSS `image-rendering: pixelated` で拡大表示。WebGL/CRTシェーダーは将来の拡張候補 |
| エミュレーション駆動 | Web Worker（`nesWorker.ts`）+ 自己補正`setTimeout`ループ | メインスレッドの`requestAnimationFrame`からは独立して実時間で自走。描画はWorkerが吐き出す最新フレームをベストエフォートで拾うだけ |
| サウンド | Web Audio API（`OscillatorNode`/`AudioBufferSourceNode`） | APUレジスタ状態を毎フレームポーリングして駆動（M5実装、[04_EMULATOR_SPEC.md](04_EMULATOR_SPEC.md)参照） |
| ROM 読み込み（外部ROM検証用） | File API（`FileReader`） | 開発時の `nestest.nes` 等の読み込みに使用。配布物には他者ROMを含めない |
| DSL パーサ | 自作の再帰下降パーサ | フル ES 文法への対応が不要なため、既存 JS パーサ（Acorn等）への依存より制御しやすい自作を採用 |
| ホスティング | GitHub Pages（静的サイト） | note には直接 HTML/JS を埋め込めないため、Web アプリ本体は外部ホスティングし note からリンク |
| オンライン対戦 | WebRTC DataChannel + STUN | サーバーコストほぼゼロで P2P 対戦を実現（ストレッチゴール） |
| レイアウト | CSS Flexbox/Grid + メディアクエリ | PC/タブレット/スマホでレイアウトを可変にする。詳細は次節「UI/UX方針」 |

> **注**: 上記スタックは会話内容から導かれた初期方針であり、実装を進める中で変更の余地がある（特に npm workspaces vs pnpm、DSLパーサの自作 vs 既存ライブラリ活用など）。

## UI/UX方針: レスポンシブ対応

本プロジェクトは PC・タブレット・スマートフォンいずれからでも「作る」「遊ぶ」「対戦に参加する」ことを想定する（[00_CONCEPT.md](00_CONCEPT.md) 非機能要件）。Web IDE・プレイ画面ともに単一のコードベースでレスポンシブ実装する。

### レイアウトの可変方針

| 画面幅 | ダッシュボードUI | 備考 |
|---|---|---|
| PC/タブレット横向き（広い） | タブ（コード/ドット絵/音源/ビルド&実行/対戦）を横並び or サイドナビ＋メインペインの2カラム構成 | エディタ類とプレビュー(`<canvas>`)を同時表示できる |
| スマホ/タブレット縦向き（狭い） | タブをボトムナビゲーション化し、1画面1タブに集約。プレビュー(`<canvas>`)は常に画面上部に固定表示できるようにする | 編集とプレイの切り替えをしやすくする |

- ブレークポイントの具体値は実装時に決定するが、方針として「PC=マルチペイン同時表示」「モバイル=シングルペイン+タブ切替」を基本形とする。
- ゲーム描画用の `<canvas>`（256×240論理解像度）は `aspect-ratio` を維持したまま画面幅に応じて可変サイズで表示し、`image-rendering: pixelated` を保つ。

### 入力方式

- **PC**: キーボード入力を基本とする（[04_EMULATOR_SPEC.md](04_EMULATOR_SPEC.md) の `$4016`/`$4017` マッピング）。
- **タッチデバイス**: 物理キーボードがない環境では、常時オンスクリーンの仮想パッド（十字キー＋A/Bボタン＋Start/Select）を表示する。
  これは [06_NETPLAY_SPEC.md](06_NETPLAY_SPEC.md) でオンライン対戦のゲスト向けに挙げた「バーチャルパッド」と同一の仕組みを、**ソロプレイ時のモバイル利用でも標準搭載**する形に一般化する。

### アセットエディタのタッチ対応

- ドット絵エディタ（[05_ASSET_EDITOR_SPEC.md](05_ASSET_EDITOR_SPEC.md)）・APUトラッカーは、タップ操作でのセル選択・パレット選択ができるよう、タップターゲットサイズを確保する。
- コードエディタ（DSL記述）のモバイルでの快適な編集体験（オンスクリーンキーボード対応、シンプル入力支援等）は実装時の検討課題とする。

### 未決事項

- 具体的なブレークポイント値、コンポーネントライブラリの採用可否（自前CSS vs 軽量UIキットの利用）。
- モバイルでのコード編集体験をどこまで作り込むか（閲覧・簡易編集のみに割り切るか、フル編集対応するか）。

## データフロー（ビルド時）

1. ユーザーがコードエディタに JS 風 DSL を記述。
2. ドット絵エディタで CHR-ROM 相当のタイルを作成し、`SPRITE.PLAYER_STAND` のようなシンボル名を付与。
3. APU トラッカーで BGM/SE を作成し、`BGM.OVERWORLD` 等のシンボル名を付与。
4. 「ビルド」を押すと、`dsl-compiler` がコードを 6502 バイナリへ、`rom-builder` がアセットデータを iNES 形式へ変換し、1つの `.nes`（`Uint8Array`）に統合。
5. 生成された `.nes` は `emulator-core` にそのままロードされ、ブラウザ内で即実行される。
6. 「.nes をダウンロード」または「配布用スタンドアロンHTMLを書き出す」を押すと、外部エミュレータ/実機互換機でも動作するファイルが手に入る。
